# 开源自托管与商用部署

SpriteKiln 的默认形态是**单人、本机、可信环境**。它可以被自托管，也可以作为商业服务的基础，但后者需要补上认证、隔离和运维层。本文把「现在能做什么」和「商用前必须做什么」分开写，避免把 demo 当 SaaS 上线。

---

## 1. 三种部署形态

| 形态 | 适用 | 现状 |
|---|---|---|
| **A. 本机单用户** | 个人开发者、美术、小团队内网 | 开箱即用，默认只监听 `127.0.0.1` |
| **B. 内网共享** | 工作室几台机器共用一台 GPU 服务器 | 可用，但需要反代 + 访问控制；所有人共享配置与素材 |
| **C. 公网商业服务** | 对外提供素材生成 | **需要二次开发**：认证、租户隔离、对象存储、外部队列、计费与限流 |

---

## 2. A：本机运行（推荐起点）

```powershell
python backend/run.py --host 127.0.0.1 --port 7788
```

- 只绑定回环地址，局域网其他机器访问不到；
- ComfyUI / Pixal3D 同样只监听本机；
- 数据在 `data/`，备份就是复制这个目录（停服务或用 SQLite `.backup`）。

这是最安全的形态，也是开发与出图的主要方式。

---

## 3. B：内网共享

把后端绑到内网地址：

```powershell
python backend/run.py --host 0.0.0.0 --port 7788
```

然后**不要**直接把 7788 暴露给整个内网。至少加一层反向代理和访问控制。

### 3.1 Caddy（自动 HTTPS，配置最少）

```caddy
spritekiln.example.com {
    basic_auth {
        studio $2a$14$REPLACE_WITH_BCRYPT_HASH
    }
    reverse_proxy 127.0.0.1:7788
}
```

Caddy 默认会正确处理 SSE/流式响应，`/api/events` 不需要额外配置。生成密码哈希：`caddy hash-password`。

### 3.2 Nginx

```nginx
server {
    listen 443 ssl;
    server_name spritekiln.example.com;

    client_max_body_size 50m;

    location / {
        auth_basic "SpriteKiln";
        auth_basic_user_file /etc/nginx/.htpasswd;
        proxy_pass http://127.0.0.1:7788;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # SSE：关闭缓冲，否则画布不会实时刷新
    location /api/events {
        auth_basic "SpriteKiln";
        auth_basic_user_file /etc/nginx/.htpasswd;
        proxy_pass http://127.0.0.1:7788;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }
}
```

### 3.3 内网共享的现实限制

- **没有用户体系**：所有访问者看到的项目、素材、设置是同一份；
- **设置页可改 Key**：任何能打开网页的人都能改模型配置；
- **任务队列在进程内**：重启会丢失排队中的任务（已完成的任务与素材在 SQLite 里）；
- **GPU 串行**：多人同时提交会排队，不会并发出图。

如果这些限制可接受（例如固定几个同事），B 形态够用；否则按下面的 C 做。

## 4. C：公网商业化前的清单

下面每一项都是当前代码**没有**或**不完整**的，按优先级排列。

### 4.1 必须补

1. **认证与授权**
   - 在 FastAPI 上加中间件或依赖，保护除健康检查外的所有路由；
   - 至少区分「管理员」（可改设置）与「普通用户」（只能用素材能力）；
   - 反向代理的 Basic Auth 只能算临时方案，不适合对外收费产品。

2. **租户隔离**
   - 目前 `projects` / `assets` / `jobs` 有 `project_id`，但没有 `owner_id`；
   - 设置（含云端 Key）是全局的；商用时应改为「平台 Key + 用户配额」或「用户自带 Key（BYOK）」；
   - `/files` 是静态目录，需要按租户校验，或改成带签名的临时 URL。

3. **数据库与队列**
   - SQLite + 进程内 `asyncio` 队列只适合单实例；
   - 多副本需要 Postgres + Redis/Celery（或同类）外部队列，并把任务状态迁移过去；
   - 上传与产物应进对象存储（S3/OSS/R2），本地磁盘只做缓存。

4. **限流与配额**
   - 按用户限制并发任务数、每日 GPU 秒数、每日云端费用；
   - 现有 `budget.daily_cloud_usd` 是**全局估算**，不是按用户的硬限额；
   - 上传大小、生成尺寸、动画帧数都要有服务端上限。

5. **可观测性**
   - 结构化日志（请求 id、任务 id、Provider、耗时、费用）；
   - 指标：队列长度、任务成功率、各 Provider 错误率、GPU 占用；
   - 告警：云端 Key 失效、预算超限、磁盘将满。

6. **备份与恢复**
   - 定时备份 SQLite/Postgres 与对象存储；
   - 演练一次「清空环境 → 恢复 → 素材可打开」；
   - 明确素材保留期与用户删除权（涉及隐私合规）。

### 4.2 建议改

- CORS：`backend/app/main.py` 现在是 `allow_origins=["*"]`，公网必须收紧到你的域名；
- 上传类型白名单与病毒扫描；
- 任务取消/超时的资源回收（尤其是外部 API 已计费但本地已放弃的任务）；
- 审计日志：谁在什么时候改了设置、删了素材；
- 把 `/docs` 与 `/openapi.json` 在公网关掉或加权限。

### 4.3 商业化还要想清楚

- **模型与内容许可**：本地模型权重、LoRA、云端 API 的商用条款各不相同；「生成的图归谁」取决于服务商条款与你的用户协议。上线前逐项确认，不要默认 MIT 覆盖模型权重。
- **成本**：本地是电费 + 硬件折旧；云端按张/按秒计费。现有预算是估算值，正式计费应以服务商账单为准。
- **SLA**：本地单卡没有高可用；GPU 故障、ComfyUI 崩溃都会让任务失败。需要重试、降级和用户可见的状态。
- **数据合规**：用户上传的参考图可能含个人信息；接云端模型意味着数据出境/第三方处理，需在隐私政策里写明。
- **开源义务**：本仓库是 AGPL-3.0（旧版本为 MIT）。自己用、自建内部服务没问题；把修改版作为网络服务提供给别人时，需要向使用者提供对应源码。闭源嵌入需另外申请商业许可，见 [10-开源与商业边界](10-开源与商业边界.md)。模型、字体、图标、示例素材各有各的许可证，需分别核对。

## 5. Docker 部署

仓库自带 `Dockerfile` 与 `docker-compose.yml`，镜像是 **CPU-only**：API + 已构建前端。

```bash
docker compose up --build
```

- 端口默认绑 `127.0.0.1:7788`，要对外请在前面的反代做 TLS 与认证；
- `./data` 挂载到 `/app/data`，容器重建不丢素材；
- ComfyUI 在宿主机时，compose 已设置 `SPRITEKILN_COMFYUI_URL=http://host.docker.internal:8188`；
- 宿主机服务必须监听 `0.0.0.0`，容器才能通过 `host.docker.internal` 访问。默认的 `127.0.0.1` 只对宿主机自身可见：

  ```powershell
  .\tools\start_comfyui.ps1 -Listen 0.0.0.0
  $env:OLLAMA_HOST = "0.0.0.0"; ollama serve
  ```

  只在内网/可信环境这么做，并配合防火墙；Linux 也可以直接用 `--network host` 代替这两个地址。
- 容器内没有 GPU 推理；ComfyUI、Pixal3D 仍需在宿主机或独立 GPU 容器中运行，并通过 HTTP 访问；
- 镜像不包含模型权重，首次使用仍需按 [07-模型配置.md](07-模型配置.md) 配置。

生产环境建议：

- 用具体 digest 固定基础镜像；
- 只读挂载代码，`data` 用独立卷；
- 设置 `restart: unless-stopped` 与健康检查（已内置 `/api/system`）；
- 反代加 `client_max_body_size`、超时和速率限制。

## 6. 备份与升级

### 备份

```powershell
# 停服务后
Copy-Item -Recurse data "backup\data-$(Get-Date -Format yyyyMMdd-HHmm)"
```

SQLite 运行时备份：

```powershell
python -c "import sqlite3; s=sqlite3.connect('data/spritekiln.db'); d=sqlite3.connect('backup/spritekiln.db'); s.backup(d); d.close(); s.close()"
```

只复制 `.db` 而漏掉 `-wal` / `-shm` 可能丢最近的事务。

### 升级

```powershell
git pull
pip install -r backend\requirements.txt
cd web; npm ci; npm run build; cd ..
python -m pytest backend/tests -q
```

数据库目前没有迁移框架；升级前先备份 `data/`。如果新版本改了表结构，用备份回滚是当前最稳妥的方式。

## 7. 安全速查表

上线前逐项打勾：

- [ ] 服务不直接暴露公网端口，前面有 TLS 反代
- [ ] 所有非健康检查路由都要求认证
- [ ] CORS 只允许自己的域名
- [ ] `/api/settings` 只对管理员开放
- [ ] `data/settings.json` 不在 Web 根目录、不进镜像、不进备份仓库
- [ ] `/files` 不能越权读取他人素材
- [ ] 上传有大小/类型限制
- [ ] 云端预算与每用户配额有服务端硬限制
- [ ] 日志不打印 Key、Token、完整请求体
- [ ] 备份可恢复，且备份本身加密
- [ ] 依赖定期扫描（`pip-audit` / `npm audit`）
- [ ] 模型与素材许可证已逐项确认
