# 模型配置

SpriteKiln 不绑定某一个模型。它把「任务」和「引擎」分开：

```text
能力（pixel_gen / animate / …）
  └─ needs: image / video / llm / threed / bg
       └─ 路由（auto 或指定 Provider）
            └─ Provider（ComfyUI / 云端 API / Ollama / Pixal3D / mock）
```

因此同一个「像素角色」按钮，可以在本机 ComfyUI、GPT Image、Seedream、甚至离线 mock 上运行。本文说明每一层怎么配。

---

## 1. 配置存在哪、谁覆盖谁

| 位置 | 内容 | 生效方式 |
|---|---|---|
| 网页 **设置** 页 | 路由、Provider 地址/模型/Key、预算、并发、Godot 路径 | 点保存立即写入 `data/settings.json`，下一次任务生效 |
| `data/settings.json` | 同上，**API Key 明文** | 服务启动时读取 |
| 环境变量 / `.env` | 默认值（ComfyUI 地址、cc-switch、本地 LLM、Pixal3D、数据目录） | 进程启动时读取 |
| `~/.cc-switch/cc-switch.db` | cc-switch 当前 provider 与模型名（**只读**，不读 Key） | 每次健康检查/对话时自动发现，10 秒缓存 |
| 能力参数 | 单次任务的 `provider` / `video_provider` / `threed_provider` / `bg_method` | 只影响该任务 |

优先级：**`data/settings.json` > 环境变量 / `.env` > 代码内置默认值**。

也就是说，一旦你在网页上保存过 `base_url`，之后改 `.env` 不会覆盖它；改配置请以网页/设置文件为准，或者删掉对应键让默认值重新生效。

`.env` 模板见仓库根目录 `.env.example`。`SPRITEKILN_DATA` 可以改数据目录（默认 `./data`）。

## 2. 路由：auto 的选人顺序

设置页每类任务都可以选「自动」或某个具体 Provider。选「自动」时，按偏好列表取**第一个健康**的：

| 任务 | 默认偏好顺序 |
|---|---|
| 生图 `image` | ComfyUI → OpenAI → 火山方舟 → MiniMax → mock |
| 图像编辑 `image_edit` | OpenAI → 火山方舟 → ComfyUI → mock |
| 动画/视频 `video` | ComfyUI → 火山方舟 Seedance → MiniMax Hailuo → procedural |
| 大模型 `llm` | **cc-switch** → 本地 LLM（Ollama/LM Studio）→ OpenAI → 方舟 → MiniMax → rules |
| 3D `threed` | Pixal3D → mock |
| 去背景 `bg` | BiRefNet → chroma |

健康检查有 15 秒缓存（cc-switch 的模型发现单独缓存 10 秒），设置页点「重新检测」可强制刷新。禁用的 Provider 直接视为不健康。

cc-switch 排第一意味着：只要它的 Codex 本地代理开着，Agent 就用你当前在 cc-switch 里选中的模型；代理没开或没装 cc-switch 时，才轮到本地 Ollama。

「自动」的兜底是有意设计的：**任何一项没配好都不会让整条流水线报错**，只会退到低一档的引擎。代价是产物质量下降，所以第一次配置后请确认路由落在你期望的引擎上。

> 单次任务覆盖：`pixel_gen` 等图像能力可传 `provider=comfyui|openai|ark|minimax|mock`；`animate` 传 `video_provider=...`；3D 传 `threed_provider=...`；去背景传 `bg_method=chroma|birefnet`。

### 通道与预算

- GPU 通道默认并发 1。单卡跑 Z-Image/H3 时不要调高，否则显存争抢会把两张都拖慢。
- 云端通道默认并发 4；CPU 通道 2。
- `budget.daily_cloud_usd` 是**估算**的每日云端上限（美元），超限后云端任务被拒绝，本地引擎不受影响；填 0 表示不限。

## 3. 本地生图 / 动画：ComfyUI

### 3.1 安装与启动

1. 安装 [ComfyUI](https://github.com/comfyanonymous/ComfyUI)（便携版或源码版均可）；
2. 确保能用 API 模式访问：`http://127.0.0.1:8188/system_stats` 返回 JSON；
3. Windows 可以用本仓库脚本：

```powershell
$env:COMFYUI_DIR = "D:\AI\ComfyUI"
.\tools\start_comfyui.ps1
```

脚本会检查 `main.py` 并监听 `127.0.0.1`。也可以自己 `python main.py --listen 127.0.0.1 --port 8188`。

### 3.2 需要哪些模型

模型文件名写在工作流的 `*.map.json` 里；下面是仓库自带的三套：

**Z-Image Turbo 文生图**（`zimage_turbo_t2i`）

| 放到 ComfyUI 的哪个目录 | 文件 |
|---|---|
| `models/diffusion_models/` | `z_image_turbo_bf16.safetensors` |
| `models/text_encoders/` | `qwen_3_4b.safetensors` |
| `models/vae/` | `ae.safetensors` |

**Z-Image Turbo 图生图**（`zimage_turbo_i2i`）使用与上面相同的三个文件。

**MiniMax H3 首尾帧动画**（`minimax_h3_fl2v`）

| 目录 | 文件 |
|---|---|
| `models/diffusion_models/` | `minimax_h3_fl2va_int8_convrot.safetensors` |
| `models/loras/MinimaxH3/` | `minimax_h3_turbo_v4_step600_comfyui_T8-convert.safetensors` |
| `models/text_encoders/` | `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` |
| `models/vae/` | `minimax_h3_video_vae_fp16.safetensors`、`minimax_h3_audio_vae_fp32.safetensors` |

H3 工作流依赖一组 `MiniMaxH3*` 自定义节点和 sage-attention patch 节点。缺节点时 ComfyUI 加载工作流会报错；请安装与你的 ComfyUI 版本匹配的 H3 节点包，或改用云端 Seedance/Hailuo。

> 文件版本会随上游更新。`map.json` 里的 `models` 是**期望的本地文件名**；如果你下载到的名字不同，改 map 或重命名文件即可。

### 3.3 在 SpriteKiln 里指向它

设置页 → **ComfyUI（本地）**：

- `地址`：`http://127.0.0.1:8188`
- `生图工作流`：`zimage_turbo_t2i`
- `重绘工作流`：`zimage_turbo_i2i`
- `视频工作流`：`minimax_h3_fl2v`
- `视频步数`：H3 Turbo 建议 8

工作流名就是 `backend/workflows/<name>.map.json` 去掉 `.map.json`。`GET /api/comfy/workflows` 会列出当前可用的工作流和它们需要的模型。

**换模型不用改工作流**：下面的字段留空时使用工作流内置的文件名；填了就覆盖对应节点。

| 字段 | 覆盖什么 | 默认文件 |
|---|---|---|
| `生图主模型` | UNET / diffusion model | `z_image_turbo_bf16.safetensors` |
| `文本编码器` | CLIP / text encoder | `qwen_3_4b.safetensors` |
| `VAE` | VAE | `ae.safetensors` |
| `视频主模型` | UNET | `minimax_h3_fl2va_int8_convrot.safetensors` |
| `视频 LoRA` | LoRA | `MinimaxH3/minimax_h3_turbo_v4_step600_...safetensors` |
| `视频文本编码器` | CLIP | `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` |
| `视频 VAE` / `音频 VAE` | 两个 VAE | `minimax_h3_video_vae_fp16.safetensors` / `minimax_h3_audio_vae_fp32.safetensors` |

路径相对 ComfyUI 的 `models/` 目录，子目录用 `/` 或 `\` 都行（例如 `loras/my_style_v2.safetensors`）。换了一个结构不同的工作流时，在它的 `map.json` 里加 `model_fields` 映射即可，无需改 Python。

### 3.4 换模型 / 加工作流

1. 在 ComfyUI 里搭好工作流，用 **Save (API Format)** 导出 JSON；
2. 放到 `backend/workflows/<name>.json`；
3. 配一个 `<name>.map.json`：`fields` 把能力参数映射到 `[节点 id, 输入名]`，`output` 是 SaveImage 节点 id；
4. 设置页把对应工作流名改过去，或直接改 `settings.json`。

不需要改 Python。细节见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 4. Agent 模型

内置 Agent（`backend/app/agent/`）负责「自然语言 → 能力执行计划」。它使用 `routing.llm` 选出的 LLM，默认「自动」时顺序是：

1. **cc-switch**（本机代理，自动跟随你当前选中的 Codex provider）
2. **本地大模型**（Ollama / LM Studio / vLLM，OpenAI 兼容）
3. **云端 LLM**（OpenAI / 火山方舟 / MiniMax）
4. **rules**（关键词规则，永远可用）

### 4.1 cc-switch（首选，自动跟随）

cc-switch 的 Codex 本地代理（默认 `127.0.0.1:15721`）本身就是 OpenAI 兼容的 chat 接口，并会替请求注入上游 Key。SpriteKiln 直接复用它：

1. 在 cc-switch 里选好 Codex provider（例如 DeepSeek），确认「本地代理」开启；
2. 启动 SpriteKiln，设置页不用填 Key；
3. 设置页 → 路由 → 大模型应显示 `cc-switch`，下方显示当前 provider 与模型名。

实现方式：**只读** `~/.cc-switch/cc-switch.db`，取 `app_type='codex'` 的当前 provider 名称、模型 ID 与代理端口；**不读取、不复制任何 API Key**，Key 始终由 cc-switch 代理注入。

可选设置（一般留空）：

| 字段 | 留空时 | 填写时 |
|---|---|---|
| 代理地址 | 自动读 cc-switch 的监听端口 | 指到另一个 OpenAI 兼容代理 |
| 模型 | 自动读当前 provider 的模型 | 强制使用该模型名 |
| Key | 不发送（代理自管） | 自定义代理需要鉴权时填 |

验证：

```powershell
curl.exe http://127.0.0.1:7788/api/ccswitch
# {"ok":true,"provider":"deepseek","model":"deepseek-v4-pro","base_url":"http://127.0.0.1:15721/v1",...}
```

这个接口永远不返回密钥。在 cc-switch 里切换 provider 后，最多 10 秒（或点「重新检测」）生效，不用重启 SpriteKiln。

> cc-switch 未安装、未启动、代理关闭、或没有当前 Codex provider 时，`/api/ccswitch` 返回 `ok:false` 和原因，路由自动落到下一项（本地大模型）。

**Docker 里运行时**：容器读不到宿主机的 `~/.cc-switch`，而且默认代理只监听 `127.0.0.1`。要么挂载 DB，要么直接指定模型并让代理监听 `0.0.0.0`：

```yaml
environment:
  SPRITEKILN_CCSWITCH_URL: http://host.docker.internal:15721/v1
  SPRITEKILN_CCSWITCH_MODEL: deepseek-v4-pro   # 容器内读不到 DB 时必须显式指定
```

### 4.2 Ollama（本地兜底）

```powershell
ollama pull deepseek-r1:8b
ollama serve          # 通常安装后已自动运行
```

设置页 → **本地大模型**：

| 字段 | 值 |
|---|---|
| 地址 | `http://127.0.0.1:11434/v1` |
| 模型 | `deepseek-r1:8b`（或 `qwen2.5:7b` 等支持 JSON 输出的模型） |
| Key | `ollama`（占位即可） |

Agent 用 JSON 模式要计划，7B–14B 一般够用；模型必须遵守「只输出 JSON」的指令，否则会自动降级到规则路由。

### 4.3 LM Studio / vLLM / llama.cpp

启动它们的 OpenAI 兼容服务器，把地址改成对应端口即可：

- LM Studio 默认 `http://127.0.0.1:1234/v1`
- vLLM 默认 `http://127.0.0.1:8000/v1`

模型名填服务器里实际加载的 ID。

### 4.4 云端 LLM

在 **OpenAI / 火山方舟 / MiniMax** 卡片里填 `api_key` 和 `llm_model`，并把 `routing.llm` 设为对应 Provider（或保持 auto 并把它排到本地之后）。

### 4.5 排错

- 设置页 cc-switch 显示不可用：看 `/api/ccswitch` 的 `detail`，确认 cc-switch 正在运行且 Codex 代理已启用。
- Agent 回复「已用规则路由」：说明 cc-switch 和本地模型都不可用，看 `/api/health` 的 `providers.llm`。
- cc-switch 里换了 provider 但 Agent 还用旧模型：等 10 秒或点「重新检测」（模型发现是短缓存）。
- 想强制不用 cc-switch：设置页把它的「启用」取消，或在 `routing.llm` 直接选别的 Provider。

## 5. 云端生图 / 视频

三家都走 OpenAI 兼容或官方 REST 适配，配置字段在设置页。Key 只保存在本机 `data/settings.json`，返回浏览器时掩码。

| Provider | 适合 | 主要字段 | 备注 |
|---|---|---|---|
| **OpenAI / 兼容中转** | GPT Image，参考图编辑、原生透明 | `base_url`、`api_key`、`image_model`、`llm_model` | 也支持任意 OpenAI 兼容中转站；模型名按你的服务填 |
| **火山方舟** | Seedream 多参考一致性、Seedance 首尾帧视频 | `base_url`、`api_key`、`image_model`、`video_model`、`llm_model` | 默认 `doubao-seedream-4-0-250828` / `doubao-seedance-1-0-pro-250528` |
| **MiniMax** | image-01 主体参考、Hailuo 视频 | `base_url`、`api_key`、`image_model`、`video_model`、`llm_model` | 默认 `image-01` / `MiniMax-Hailuo-02` |

模型名只是默认值，服务商上新后直接在设置页改字符串即可，不用改代码。

云端任务会累计估算费用到当日预算；超预算会拒绝，而不是偷偷继续扣费。

## 6. 3D：Pixal3D

Pixal3D 是独立仓库和独立 venv，SpriteKiln 通过子进程调用它。

1. 克隆 Pixal3D 到任意目录；
2. 为它建 venv 并装好依赖（按其 README）；
3. 设置页 → **Pixal3D（本地 3D）**：
   - `仓库目录`：Pixal3D 根目录
   - `venv Python`：该环境里的 `python.exe`
   - `分辨率`：3090 建议 1024
   - `低显存模式`：勾选
4. 或者用环境变量：

```powershell
$env:SPRITEKILN_PIXAL3D_REPO = "D:\AI\Pixal3D"
$env:SPRITEKILN_PIXAL3D_PYTHON = "D:\AI\Pixal3D\.venv\Scripts\python.exe"
```

`repo` 为空时 Pixal3D 显示「未配置」，3D 路由退回 mock（billboard），不会阻塞其他功能。

Windows 上如果 Pixal3D 依赖有损坏，可以运行 `tools\fix_pixal3d.ps1`；它用 `PIXAL3D_DIR` / `COMFYUI_DIR` 环境变量定位目录，缺变量时会给出中文提示。

完整管线见 [03-3D管线.md](03-3D管线.md)。

## 7. 去背景：BiRefNet

默认顺序是 BiRefNet → chroma。BiRefNet 是可选依赖，而且**只从本地 Hugging Face 缓存加载**（`local_files_only=True`），不会在任务中偷偷联网。

```powershell
pip install torch torchvision transformers timm einops kornia
huggingface-cli download ZhengPeng7/BiRefNet
```

没有权重或没装 torch 时，`/api/health` 会显示不可用，自动改用 chroma。纯色背景（尤其绿幕/品红幕）用 chroma 往往更快更准；复杂背景再用 BiRefNet。

## 8. 完全离线：mock / procedural

| Provider | 行为 | 用途 |
|---|---|---|
| `mock`（生图/3D） | 程序化色块、billboard | 验证队列、参数、导出、CI |
| `procedural`（动画） | 程序化帧序列 | 验证帧数、命名、Sprite Sheet |
| `rules`（LLM） | 关键词路由 | 没有 LLM 时也能执行简单需求 |
| `chroma`（抠图） | 纯色键控 | 无 GPU 的确定性抠图 |

离线产物**不是美术**，但它们是确定性的，适合写测试和压测流水线。CI 就是只用这套跑完 20 个测试的。

## 9. 配置完成后的验收

```powershell
# 1. 服务与路由（Windows PowerShell 用 curl.exe；macOS/Linux 用 curl）
curl.exe http://127.0.0.1:7788/api/health

# 2. 当前设置（Key 会被掩码）
curl.exe http://127.0.0.1:7788/api/settings

# 3. Agent 的首选模型来源（不返回密钥）
curl.exe http://127.0.0.1:7788/api/ccswitch

# 4. 真实生成一张
python skills\spritekiln-game-assets\kiln_api.py run pixel_gen `
  --param template=px_icon_32 --param "prompt=red potion" --output-dir .\out\check
```

`/api/health` 里重点看：

- `routes`：每类任务最终落在哪个 Provider；
- `providers.<kind>.<name>.ok`：是否健康；
- `detail`：失败原因（连接拒绝、模型缺失、Key 无效等）。

如果 `ok=false` 但任务仍成功，说明路由落到了兜底引擎——这时候产物质量可能不是你想要的，按本文对应章节修正。
