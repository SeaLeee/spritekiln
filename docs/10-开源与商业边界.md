# 开源与商业边界

SpriteKiln 采用 **open core**：本地创作工具完整开源，托管服务（登录、计费、多租户、算力调度）作为独立的私有项目维护。

这么分的目的不是「锁功能」，而是让本地版可以放心用、放心改，同时让托管服务的成本（GPU、带宽、运维、合规）有对应的收入。

## 这个仓库包含什么

| 模块 | 是否开源 | 说明 |
|---|---|---|
| `backend/app/` | ✅ AGPL-3.0 | 能力目录、Provider 路由、任务队列、像素算法、导出、Agent |
| `backend/workflows/` | ✅ | ComfyUI 工作流与字段/模型映射 |
| `web/` | ✅ | 完整前端（工作台、画布、设置、项目、策划） |
| `skills/`、`mcp/` | ✅ | CLI/Skill、MCP server |
| `tools/` | ✅ | ComfyUI / Pixal3D 辅助脚本 |
| `docs/` | ✅ | 安装、模型配置、部署、同类对比 |

**本地版没有功能阉割**：26 个能力、所有导出格式、Agent、批量、3D 都在这里。

## 不在这个仓库的部分

托管服务（另一个私有仓库）负责：

- 账号、登录、会话与 API Key；
- 多租户隔离、项目配额、并发限制；
- 积分账本、支付回调、退款；
- 云端 GPU worker 池与调度（包含「家庭机器作为出站 worker」）；
- 对象存储、签名 URL、审计日志、运营后台；
- 计费页面与团队席位。

这些代码与本地版通过 **HTTP 任务协议** 解耦：云端把任务派给 worker，worker 调用本地 SpriteKiln 的 `/api/capabilities/{id}/run` 并把产物传回。也就是说，你完全可以自己在内网搭一套调度，而不依赖官方托管服务。

## 商标

「SpriteKiln 像素窑」名称与 Logo 不在 AGPL 授权范围内。基于本仓库的分支可以保留版权声明和「基于 SpriteKiln」的说明，但不要用官方名称/Logo 暗示官方背书。

## 贡献

为了让项目能同时以 AGPL 和商业许可分发，外部贡献需要签署 [CLA](CLA.md)。只改文档、修错别字也欢迎，流程相同。
