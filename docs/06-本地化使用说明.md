# 本地化使用说明（从零到第一套素材）

本文按「克隆 → 安装 → 启动 → 出第一张图 → 做动画 → 导出引擎」的顺序写。命令以 Windows 为主，macOS / Linux 的差异单独标注。

> 先说明一个重要的默认行为：**ComfyUI 没启动、也没有云端 Key 时，SpriteKiln 会自动退到 mock / procedural（离线程序化）引擎**。所以你可以先零配置把整条流程跑通，再逐个接真实模型。离线产物只用于验证流程和参数，不是最终美术。

---

## 0. 你需要什么

| 依赖 | 版本 | 必填 | 用途 |
|---|---|---|---|
| Python | 3.10+ | 是 | 后端、CLI、Skill |
| Node.js + npm | 18+（推荐 20/22） | 构建前端时必填 | `web/` 的 Vite 构建；只在开发或首次构建时需要 |
| ComfyUI | 最新版 | 否 | 本地生图 / 图生图 / 动画（Z-Image Turbo、MiniMax H3） |
| Ollama / LM Studio | 最新版 | 否 | 内置 Agent 的规划大模型 |
| NVIDIA GPU | 8GB+ 显存（像素够用） | 否 | 本地模型推理；3D 与 H3 动画建议 16GB+ |
| Pixal3D 仓库 + 独立 venv | — | 否 | 单图转 3D GLB |
| BiRefNet 权重 | — | 否 | 神经抠图；没有时用纯色键控 |
| 磁盘 | 5GB+ | 是 | 依赖、素材、模型（模型另算） |

只跑后端 API、不出图的话，Python 就够；前端是已经构建好的静态文件时也不需要 Node。

## 1. Windows：一键启动

```powershell
git clone https://github.com/sealeee/spritekiln.git
cd spritekiln

# 建议用独立虚拟环境，避免污染系统 Python
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt

.\start.ps1
```

`start.ps1` 会做三件事：

1. 如果 `web/dist` 不存在（或加了 `-Build`），先 `npm install && npm run build`；
2. 检查 `http://127.0.0.1:8188` 上的 ComfyUI，没启动就在新窗口运行 `tools\start_comfyui.ps1`；
3. 启动后端并打开 `http://127.0.0.1:7788`。

常用参数：

```powershell
.\start.ps1 -NoComfy     # 不启动 ComfyUI（用云端或离线引擎）
.\start.ps1 -Build       # 重新构建前端
.\start.ps1 -Port 7799   # 换端口
```

> 如果 PowerShell 提示禁止运行脚本：
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

---

## 2. macOS / Linux：手动启动

```bash
git clone https://github.com/sealeee/spritekiln.git
cd spritekiln
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt

# 构建前端（Node 18+）
cd web && npm ci && npm run build && cd ..

python backend/run.py --host 127.0.0.1 --port 7788
```

`start.ps1`、`tools/*.ps1` 是 Windows 辅助脚本；其他平台直接运行 `python backend/run.py`，ComfyUI 用你自己的启动方式，然后在设置页填 `base_url`。

Docker（CPU、无本地 GPU 模型）：

```bash
docker compose up --build
# 打开 http://127.0.0.1:7788
```

ComfyUI 在宿主机时，compose 已把 `SPRITEKILN_COMFYUI_URL` 指到 `http://host.docker.internal:8188`。注意宿主机的 ComfyUI/Ollama 需要监听 `0.0.0.0` 才能被容器访问：`.\tools\start_comfyui.ps1 -Listen 0.0.0.0`，Ollama 则设置 `$env:OLLAMA_HOST="0.0.0.0"` 后启动。

## 3. 第一次打开：确认引擎

打开 `http://127.0.0.1:7788`，进 **设置** 页：

- 上方「路由」显示每类任务的当前引擎，右侧小圆点是各 Provider 的健康状态；
- 「cc-switch」一行显示它当前跟随的 Codex provider 与模型；没安装/没启动时会写明原因，不影响其他功能；
- 点「重新检测」会强制刷新；
- 想确认后端是否活着：`http://127.0.0.1:7788/docs`（API 文档）或 `http://127.0.0.1:7788/api/health`。

没有配置任何模型时，健康的组合是：

| 任务 | 引擎 | 说明 |
|---|---|---|
| 生图 | `mock` | 生成占位色块/程序化像素图 |
| 动画 | `procedural` | 程序化动作，不调用视频模型 |
| 大模型 | `rules` | 关键词路由生成执行计划 |
| 3D | `mock` | billboard 占位 |
| 去背景 | `chroma` | 纯色键控/洪水填充 |

这套组合可以完整走通「提交任务 → 轮询 → 下载 → 导出」的链路，适合先验证安装。

## 4. 出第一张素材

1. 左侧进入 **工作台 / 新建项目**，例如 `forest-demo`。
2. 选择 **像素角色**（`pixel_gen`，模板 `px_char_64`）。
3. 提示词用短句：`forest ranger with a leaf cloak, friendly, front view`。
4. 提交后，任务进入队列；画布上会出现生成结果，点开可以预览、收藏、继续派生。
5. 在产物卡片上选择下载，或直接 **导出 ZIP**。

要点：

- 模板决定尺寸、数量、排列（例如 4 个 64×64 角色），提示词不能改这些；
- 像素能力会把调色板锁定、做透明裁切和 NEAREST 放大，**不要再次像素化**它的产物；
- 每次生成的原始图和预览都保留在服务器上，下载默认只取最终产物（`role=output`）。

---

## 5. 做一段动画

动画不是从零生成，而是**从一张定稿素材出发**：

1. 选一张已经有透明背景的静态角色（或先用 `remove_background` 处理）；
2. 选择 **帧动画**（`animate`）；
3. 动作描述：`walk cycle to the right` / `挥剑攻击` / `idle breathing`；
4. 帧数 8–16、帧率 10–12 起步；循环动画打开；
5. 高级参数里保留 **质量门控 = 标准**、**重拍 = 1**。

系统会：视频模型生成动作 → 逐帧键控抠图 → 锁回源调色板 → 锚点对齐 → 打包 Sprite Sheet + GIF/WebP + Godot SpriteFrames + Aseprite/Phaser JSON。

质量门控检查的是可机械判断的问题：空帧、主体面积剧烈波动、尺寸漂移、重复帧。它**不会**因为角色在画面里移动而判失败（跳跃/攻击本来就该动）。

离线模式（`procedural`）也能跑完整条动画链路，用来验证帧数、命名、导出格式。

---

## 6. 导出到游戏引擎

- **ZIP**：项目页「导出」→ 包含 PNG、Sprite Sheet、`sheet.json`、`aseprite.json`、`phaser.json`、图块的 `.tsj`、`manifest.json`。
- **Godot**：填 Godot 项目目录，导出会在 `res://assets/spritekiln/<project>/` 下写 PNG、`.tres`（SpriteFrames）、`sprite.tscn`（AnimatedSprite2D），并把纹理过滤设为 Nearest。
- **Aseprite / Phaser / Tiled**：JSON 就在动画文件夹里，帧矩形是**绝对坐标**，可直接被引擎读取，不需要再算行列。

## 7. 用 Agent 做批量

### 7.1 内置 Agent（网页聊天）

工作台右侧的 Agent 输入自然语言，例如：

> 做 4 个 64px 的森林小怪，然后给第一个做走路动画

它会输出一个执行计划（JSON），逐步提交任务；后续步骤用 `$prev` / `$stepN` 引用上一步产物。没有可用 LLM 时自动降级为关键词规则路由。

等待期间对话框会实时显示「正在思考 · 模型名」、已用秒数和模型的思考过程（折叠面板），不会只剩一个转圈。计划生成后，思考内容会收进消息里的「思考过程」，随时可以展开回看。

配置 Agent 的模型见 [07-模型配置.md](07-模型配置.md#4-agent-模型)。

### 7.2 CLI / Skill

```powershell
# 健康检查
python skills\spritekiln-game-assets\kiln_api.py health

# 单个任务
python skills\spritekiln-game-assets\kiln_api.py run pixel_gen `
  --param template=px_char_64 --param "prompt=forest ranger" `
  --output-dir .\out\ranger
```

把 `skills\spritekiln-game-assets` 链接到 Claude Code 的 skills 目录后，直接说需求即可（详见该目录的 `SKILL.md`）。

### 7.3 批量 manifest

```powershell
python skills\spritekiln-game-assets\kiln_api.py batch examples\pack.example.json --output-dir .\out\forest-pack
```

manifest 结构：

```json
{
  "output_dir": "./outputs/forest-pack",
  "stop_on_error": false,
  "items": [
    {"name": "hero", "capability": "pixel_gen",
     "params": {"template": "px_char_64", "prompt": "forest ranger", "seed": 101}}
  ]
}
```

- 每项都会写 `batch_report.json`，失败的项记录错误但默认继续；
- `--stop-on-error` 或 `stop_on_error: true` 遇到失败立即停止；
- 每项输出到 `<output_dir>/<name>/`，包含 `final_outputs.json`；
- 批量是**串行**的，GPU 任务不会互相抢显存。

### 7.4 MCP

```powershell
claude mcp add spritekiln -- python "<repo>\mcp\spritekiln_mcp.py"
```

提供 11 个工具：健康检查、能力目录/参数、运行能力、恢复任务、项目/素材、上传、Godot 导出、Agent 对话。

## 8. 常见问题

**Q：`npm` 不是内部或外部命令**  
装 Node 18+ 后重开终端。只跑后端可以跳过构建，但网页打不开；此时访问 `http://127.0.0.1:7788/` 会提示「前端未构建」。

**Q：7788 端口被占用**  
`.\start.ps1 -Port 7799` 或 `python backend/run.py --port 7799`。

**Q：设置页里 ComfyUI 是红的**  
ComfyUI 没启动、地址不对，或模型缺失。先直接访问 `http://127.0.0.1:8188/system_stats`；再检查 `models/` 下的文件是否与工作流 map 中的名字一致。详见 [07-模型配置.md](07-模型配置.md)。

**Q：Agent 总是说「已用规则路由」**  
说明 cc-switch 和本地 LLM 都不可用。先看设置页的 cc-switch 状态或 `http://127.0.0.1:7788/api/ccswitch`：cc-switch 在跑且 Codex 代理开启时，Agent 会自动用它；否则确认 Ollama 在跑、模型已 `ollama pull`、设置页「本地大模型」的地址和模型名正确。规则路由仍能干活，只是不理解复杂需求。

**Q：生成的图没有透明背景**  
像素/角色能力默认会抠图，但纯色背景不干净时会失败。改用 `remove_background`，或在参数里指定 `bg_method=chroma` / `birefnet`。BiRefNet 需要权重已缓存。

**Q：动画帧数不对 / 有多余帧**  
循环动画会多请求一帧再丢掉尾帧；如果模型返回帧数不足，导出仍是实际帧数。先看任务详情里的 `qa` 报告。

**Q：想清空数据重来**  
停止服务，备份后删除 `data/`（含 SQLite、素材、settings.json）。下次启动会重建。

**Q：能多人同时用吗？**  
当前是单用户设计：SQLite + 进程内队列，没有登录与租户隔离。公网/商用部署请先读 [08-开源自托管与商用部署.md](08-开源自托管与商用部署.md)。

## 9. 数据放在哪

| 路径 | 内容 |
|---|---|
| `data/spritekiln.db` | 项目、素材索引、任务、消息 |
| `data/projects/<id>/` | 生成的 PNG/动画/3D，以及原件 |
| `data/settings.json` | 路由与模型配置（API Key 明文，勿提交） |
| `web/dist/` | 构建后的前端 |

备份：停服务后整体复制 `data/`；或在运行时用 SQLite 的 `.backup`。不要只拷 `.db` 而漏掉 `-wal` / `-shm`。
